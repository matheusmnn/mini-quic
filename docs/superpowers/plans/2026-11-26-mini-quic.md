# mini-quic Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Protocolo de transferência confiável de arquivos sobre UDP (inspirado no QUIC), com janela deslizante Selective Repeat, mini-CDN, experimentos de desempenho e 4 bônus.

**Architecture:** Camadas de baixo para cima — `netsim` (UDP + perda/atraso artificiais assíncronos) → `reliability` (Selective Repeat) → `connection` (Connection ID, handshake 1-RTT, controle confiável, migração) → `server`/`client`. Métricas alimentam um dashboard Flask; um harness roda os 4 cenários e gera gráficos.

**Tech Stack:** Python 3.10+, stdlib (`socket`, `struct`, `zlib`, `hashlib`, `threading`, `heapq`, `json`, `argparse`), `pytest` (testes), `matplotlib` (gráficos), `Flask` (dashboard).

**Spec:** `docs/superpowers/specs/2026-11-26-mini-quic-design.md`

## Global Constraints

- Python 3.10+; só stdlib + `matplotlib` + `Flask` (nada de framework de rede pronto).
- Cabeçalho fixo de **28 bytes**, `struct` `!QBBHIIHHI`, big-endian (design §8.1).
- Payload de DATA: **1024 bytes** (constante `MAX_PAYLOAD`).
- Checksum: **CRC32** (`zlib.crc32`) sobre cabeçalho(checksum=0)+payload.
- Integridade do arquivo: **SHA-256** (`hashlib`).
- Experimentos com arquivo **≥ 80 MB**; perda/atraso **determinísticos por seed**.
- Um cliente por vez no servidor (design §12).
- Commits **apenas no nome do usuário** — sem `Co-Authored-By` / sem menção ao Claude (ver `CLAUDE.md`).
- README e relatório em **Português** (relatório no modelo SBC).

## Review Focus

- **Pacote corrompido** (CRC32 inválido) deve ser descartado e retransmitido, nunca entregue à aplicação → coberto no Task 1 (detecção) e Task 3 (retransmissão).
- **Mensagem de controle perdida** (`FILE_META`/`LIST_RESP`) nos cenários de 5% não pode travar a transferência → stop-and-wait com retry, coberto no Task 4.
- **DATA duplicado ou fora de ordem** deve ser entregue uma única vez e em ordem → coberto no Task 3.
- **Hash final divergente** deve gerar erro e descartar o arquivo, nunca salvá-lo como válido → coberto no Task 6.
- **Migração de conexão** (cliente troca de porta no meio da transferência) deve continuar pela `conn_id` → coberto no Task 4.

## Task 2: netsim — perda e atraso assíncronos

**Files:**
- Create: `mini_quic/netsim.py`
- Test: `tests/test_netsim.py`

**Interfaces:**
- Consumes: nada (opera sobre um `socket.socket` real injetado).
- Produces:
  - `class NetSim(sock: socket.socket, rtt_ms: float = 0, loss: float = 0.0, seed: int = 0)`
  - `NetSim.sendto(data: bytes, addr) -> None` — com prob. `loss` descarta; senão agenda o envio real após `rtt_ms/2` ms.
  - `NetSim.recvfrom(bufsize: int) -> tuple[bytes, addr]` — delega a `sock.recvfrom` (o atraso já foi aplicado pelo par no envio).
  - `NetSim.close() -> None`
  - contadores `sent`, `dropped`.

> Nota de arquitetura (design §8.7): o atraso NÃO bloqueia `sendto`. Uma thread de agendamento mantém um heap `(deliver_time, seq_local, data, addr)`; o laço dorme até o próximo horário e então chama `sock.sendto`. Cada ponta aplica `rtt/2` no envio → round-trip = `rtt`. A perda é decidida no `sendto` com um `random.Random(seed)` próprio (reprodutível).

## Task 3: reliability — Selective Repeat

**Files:**
- Create: `mini_quic/reliability.py`
- Test: `tests/test_reliability.py`

**Interfaces:**
- Consumes: `Packet`, `MsgType`, `MAX_PAYLOAD` (Task 1).
- Produces:
  - `class SRSender(send_fn: Callable[[Packet], None], conn_id: int, stream_id: int, window: int, rto: float)`
    - `send(data: bytes) -> None` — fragmenta em chunks de `MAX_PAYLOAD`, mantém janela de até `window` pacotes não-confirmados, retransmite por timeout (`rto`), bloqueia até tudo confirmado. Respeita `min(window, janela_anunciada)` quando ACKs trazem `window` (design §8.4).
    - `feed_ack(pkt: Packet) -> None` — processa `ack` cumulativo + bitmap SACK.
    - atributo `retransmissions: int`.
  - `class SRReceiver(send_fn: Callable[[Packet], None], conn_id: int, stream_id: int, window: int)`
    - `feed_data(pkt: Packet) -> None` — bufferiza fora de ordem, responde `ACK` (cumulativo + bitmap) via `send_fn`.
    - `delivered() -> bytes` — bytes entregues em ordem até agora.
    - `is_complete(total_bytes: int) -> bool`.

> `send_fn` desacopla do socket: o dono (connection) liga seu laço de recepção a `feed_ack`/`feed_data`. Nos testes, um `send_fn` roteia pacotes entre sender e receiver com um filtro de perda determinístico.

- [ ] **Step 1: Write failing tests** em `tests/test_reliability.py`:

```python

    assert sender.retransmissions > 0

def test_duplicate_data_delivered_once():
```

- [ ] **Step 3: Implement** `reliability.py`. Sender: dict `seq -> (pacote, horário_envio)`, thread de retransmissão varrendo a janela a cada `rto/4`; `base`/`next_seq`; `Condition` para acordar quando ACK desliza a base; encerra quando `base == total_chunks`. Receiver: `expected`, buffer `dict[seq]->payload`, monta bitmap dos recebidos acima de `expected`.

## Task 4: connection — Connection ID, handshake 1-RTT, controle confiável, migração

**Files:**
- Create: `mini_quic/connection.py`
- Test: `tests/test_connection.py`

**Interfaces:**
- Consumes: `Packet`, `MsgType` (Task 1); `NetSim` (Task 2); `SRSender`/`SRReceiver` (Task 3).
- Produces:
  - `class Connection(transport, peer_addr, conn_id: int, is_server: bool)`
    - laço de recepção (thread) que lê pacotes e despacha por `msg_type`/`stream_id`.
    - `request(pkt: Packet, expect: MsgType, retries: int = 5, timeout: float = 1.0) -> Packet` — **stop-and-wait com retransmissão** para mensagens de controle; levanta `TimeoutError` após `retries`.
    - `send_control(pkt: Packet) -> None`, `send_data_stream(stream_id, data)`, `recv_data_stream(stream_id, total_bytes) -> bytes` (usam SR).
    - `update_peer_addr(addr) -> None` — **migração**: troca o endereço do par mantendo `conn_id` e o estado da transferência.
  - `client_handshake(transport, server_addr, password: str) -> Connection` — gera `conn_id` aleatório, envia `HELLO{senha}`, espera `HELLO_ACK` (1-RTT); levanta `AuthError` em `ERROR`.
  - `server_accept(transport, addr, pkt: Packet, password: str) -> Connection | None` — valida senha; responde `HELLO_ACK` ou `ERROR`.
  - `AuthError(Exception)`.
